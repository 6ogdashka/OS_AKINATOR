# Бой Акинаторов (Akinator Battle)

Онлайн-дуэль «угадай персонажа» для **двух** игроков: авторитетный TCP-сервер и два
GUI-клиента (Qt Widgets). Каждый игрок загадывает персонажа из вшитого набора
(60 персонажей × 139 вопросов), затем по очереди задаёт вопросы и пытается первым
угадать персонажа соперника. Ответы на вопросы вычисляет **только сервер** — по
таблице признаков загаданного персонажа; клиент никогда не считает ни ответ, ни
победителя.

## Возможности

- Лобби строго на 2 игрока: третий получает `error` «Сервер занят» и отключается.
- Авторитетная фильтрация кандидатов: обычный вопрос лишь сообщает ответ — таблицу
  игрок сокращает вручную («Открыть таблицу» → «Удалить выбранных»); подсказка же
  сама выбирает вопрос и сразу убирает неподходящих.
- Три «ML-подсказки» (по одной на игрока за партию): дисперсия, Random Forest,
  CatBoost-подобный бустинг — детерминированные, живут в `gamecore`.
- Таблица кандидатов с ручным удалением, угадывание, реванш, корректная обработка
  отключений.
- Тёмная фиолетово-золотая тема и иллюстрации состояний Акинатора (ожидание,
  размышление, победа, поражение) — всё в Qt-ресурсах, работает без интернета.

## Требования

- **Qt 6.5+** (модули Core, Network, Widgets, Test), **CMake ≥ 3.16**,
  компилятор с **C++17** (проверено: GCC 16 / Qt 6.12 / CMake 4.4 на Linux).
- Python 3 — **только** для офлайн-генератора данных (в рантайме не нужен).

## Сборка

```bash
cd akinator-battle
cmake -S . -B build
cmake --build build
```

Бинарники складываются в `build/bin`:

| Файл | Назначение |
|---|---|
| `akinator-server` | сервер (Qt Core + Network) |
| `akinator-client` | GUI-клиент (Qt Widgets) |
| `tst_gamecore`, `tst_protocol` | unit-тесты |
| `libgamecore.so` / `gamecore.dll` | SHARED-библиотека игрового ядра |
| `libakinator_protocol.a` | STATIC-библиотека протокола |

`build/bin` — единая папка вывода (важно для Windows: `.dll` рядом с `.exe`).

## Генерация данных

Данные уже закоммичены (`gamecore/generated/data.h`, `data.cpp`). Пересобрать из
CSV:

```bash
python3 tools/generate_data.py
```

Скрипт читает `data/selected_characters.csv` (60 строк персонажей × (1 + 139)
колонок) и подтверждает `OK: 60 персонажей, 139 вопросов, 8340 значений матрицы`.
Формат значений: `1` — «да», `-1` — «нет».

## Тесты

```bash
ctest --test-dir build --output-on-failure
```

- `tst_gamecore` — 14 тестов: целостность данных, `value`, `filterCandidates`
  (yes/no/пусто/порядок), все три подсказки (валидность, детерминизм, отсутствие
  информации).
- `tst_protocol` — 14 тестов: разбор всех клиентских сообщений, сериализация
  серверных (`answer`, `matchover`), невалидный вход (включая числа вне `int` и
  дробные id), неизвестный тип, проверка `start`, кадрирование двух сообщений в
  одном буфере (в том числе CRLF), round-trip таблицы всех 20 типов и трёх подсказок,
  допустимость `remaining`/`count` = 60 (полный набор кандидатов).

## Запуск сервера

```bash
GAME_SERVER_PORT=9999 ./build/bin/akinator-server
```

Вывод: `Сервер слушает 0.0.0.0:9999`. Сервер слушает `QHostAddress::Any`.
Порт по умолчанию — `9999`; некорректное значение (не число / вне `1..65535`)
заменяется на дефолт с предупреждением в stderr.

## Запуск клиента

```bash
GAME_SERVER_HOST=127.0.0.1 GAME_SERVER_PORT=9999 ./build/bin/akinator-client
```

Поля «Адрес сервера» и «Порт» предзаполняются из env, но **приоритет у значений в
полях GUI** в момент нажатия «Подключиться». Пустой host → `127.0.0.1`,
некорректный порт → `9999` (предупреждение в статусной строке).

## Windows: сборка и подключение

1. Установить **Qt 6.5+** (комплект `MSVC 2019/2022 64-bit`), **CMake ≥ 3.16** и
   **Visual Studio Build Tools** (C++ workload). Проще всего — Qt Online Installer,
   он же ставит Qt Creator, Ninja и CMake.
2. Собрать из консоли `x64 Native Tools Command Prompt for VS 2022` (путь к Qt
   подставьте свой):

```bat
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=C:\Qt\6.9.3\msvc2022_64 -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Для комплекта `mingw_64` вместо Ninja: `-G "MinGW Makefiles"`. Без
`CMAKE_PREFIX_PATH` CMake не найдёт Qt6 (`Could not find a package configuration
file for "Qt6"`).

3. Windows не ищет Qt-DLL по PATH — разложить их рядом с `.exe` (делается один раз
   после сборки):

```bat
C:\Qt\6.9.3\msvc2022_64\bin\windeployqt.exe --release build\bin\akinator-client.exe
C:\Qt\6.9.3\msvc2022_64\bin\windeployqt.exe --release build\bin\akinator-server.exe
```

`gamecore.dll` уже лежит в `build\bin` — папка `bin` общая для всех бинарников,
поэтому `.exe` нельзя переносить поодиночке.

4. Подключение — **полями в окне**: «Адрес сервера» = IP машины с сервером
   (например `192.168.1.10`), «Порт» = `9999`, кнопка «Подключиться». Либо
   переменными окружения (они лишь предзаполняют поля):

> Важно: `127.0.0.1` — это **сам клиентский компьютер**. Если сервер запущен на
> другой машине (или на Linux рядом), в поле нужен её сетевой IP, иначе Windows
> отвечает `Connection refused` — на этом ПК порт никто не слушает. При игре через
> ZeroTier/Tailscale вводится адрес сервера в этой виртуальной сети (см. «Сетевой
> доступ»).

```bat
set GAME_SERVER_HOST=192.168.1.10
set GAME_SERVER_PORT=9999
build\bin\akinator-client.exe
```

PowerShell — свой синтаксис (запись `VAR=value prog` из bash/cmd там не работает):

```powershell
$env:GAME_SERVER_HOST = "192.168.1.10"
$env:GAME_SERVER_PORT = "9999"
.\build\bin\akinator-client.exe
```

5. Второй игрок — **второй процесс** того же `.exe` (один клиент = один игрок).
   Третий подключившийся получает `error` «Сервер занят» и отключается.
6. Сервер (`akinator-server.exe` или на Linux) должен быть доступен по сети: порт
   `9999` открыт (Windows Firewall → входящее правило; Linux →
   `sudo ufw allow 9999/tcp`), для игры через интернет — проброс порта на роутере.
   Проверка с клиентской машины:

```powershell
Test-NetConnection 192.168.1.10 -Port 9999
```

**Типичные проблемы**

| Симптом | Причина / решение |
|---|---|
| `Connection refused — по адресу 127.0.0.1:9999 никто не принимает подключения` | в поле остался локальный адрес, а сервер на другой машине: вписать её IP; либо сервер не запущен / другой порт. Клиент показывает этот разбор сам, с указанием испробованного адреса |
| `Connection refused` при правильном IP | сервер не запущен, слушает другой порт или порт закрыт фаерволом (RST вместо таймаута) |
| Играю через ZeroTier, а всё равно `Connection refused` | в поле должен быть ZT-адрес **сервера** (обычно `10.x.x.x`), а не свой ZT-адрес и не `127.0.0.1` — см. «Сетевой доступ → ZeroTier» |
| Приложение не стартует, «не найден Qt6Widgets.dll» | не выполнен шаг 3 (`windeployqt`) |
| «Не найден gamecore.dll» | `.exe` вынесен из `build\bin` — вернуть или скопировать DLL рядом |
| «Сервер занят» при третьем клиенте | лобби строго на 2 игрока, закройте лишний клиент |
| В логах консоли кракозябры вместо русского | `chcp 65001` в `cmd` перед запуском |

## Оформление интерфейса

Клиент использует тёмную фиолетово-золотую тему `client/style.qss` (палитра взята
с иллюстраций Акинатора) и принудительный стиль Fusion — вид одинаков на
Windows/macOS/Linux. Тема применяется в `client/main.cpp` через
`QApplication::setStyleSheet`, картинки и QSS вшиты в бинарник через
`client/resources.qrc` (AUTORCC), поэтому клиенту не нужны файлы рядом с `.exe`.

| Состояние | Файл | Когда показывается |
|---|---|---|
| Ожидание | `client/assets/state_idle.png` | экран подключения, ход соперника, ожидание ответа |
| Размышление | `client/assets/state_think.png` | ваш ход, выбор секрета |
| Победа | `client/assets/state_happy.png` | партия выиграна |
| Поражение | `client/assets/state_hard.png` | партия проиграна |

Чтобы заменить иллюстрации, положите новые PNG с теми же именами в
`client/assets/` и пересоберите проект — CMake перегенерирует ресурсы.

## Как играть

1. Запустить сервер, затем **два** клиента (можно на разных машинах).
2. Оба клиента нажимают «Подключиться» → сервер выдаёт `welcome` (игрок 1 / 2).
3. Каждый загадывает персонажа в списке 60 имён (есть поиск) и жмёт «Загадать
   выбранного». Когда секрет задан, кнопка и список блокируются.
4. Когда оба загадали → `start`, ход у игрока 1.
5. В свой ход доступны:
   - **«Задать вопрос»** — диалог со 139 вопросами и поиском; уже заданные
     исключены;
   - **«Подсказка: дисперсия / Random Forest / CatBoost»** — по одной на партию;
     подсказка сама выбирает вопрос, применяет ответ и сразу убирает
     неподходящих кандидатов;
   - **«Открыть таблицу»** — текущие кандидаты + «Удалить выбранных» (`remove`);
     обычный вопрос таблицу **не** фильтрует: после ответа откройте таблицу и
     уберите тех, кто, по-вашему, не подходит;
   - **«Угадать»** — выбор из текущих кандидатов (`guess`).
6. Правильная догадка → `matchover` обоим; неверная → `guess_result(false)` и ход
   переходит сопернику.
7. После матча — «Реванш» (нужно согласие обоих) или «Выход».
8. Разрыв соединения одним игроком → второй видит «Противник отключился», лобби
   освобождается.

## Сетевой доступ

Архитектура клиент-сервер (P2P нет): достаточно открыть/пробросить один TCP-порт
(по умолчанию `9999`) на машине с сервером и указать её адрес в клиентах
(`GAME_SERVER_HOST=<IP или домен>`). NAT traversal, UPnP, STUN/TURN и relay не
используются.

### ZeroTier

Если оба игрока в одной сети ZeroTier, проброс портов и публичный IP не нужны —
клиент обращается к **ZeroTier-адресу сервера** (обычно `10.x.x.x`), а не к
локальному `192.168.x.x` и не к `127.0.0.1`.

1. Оба устройства в одной ZT-сети и **авторизованы** (в `my.zerotier.com` у member
   стоит галочка, статус `OK`). Неавторизованное устройство просто не пустит —
   это таймаут, а не `Connection refused`.
2. Узнать ZT-адрес машины с сервером:
   - Linux: `ip -4 addr show | grep zt` (или `sudo zerotier-cli listnetworks`);
   - Windows: иконка ZeroTier в трее → `Network Details` → `Managed IPs`.
3. Сервер настраивать не нужно: он слушает `QHostAddress::Any`, то есть и на
   `zt*`-интерфейсе (`ss -ltn | grep 9999` → `*:9999`).
4. В клиенте: «Адрес сервера» = ZT-адрес **сервера**, порт `9999`.
5. Проверка с клиентской машины: `Test-NetConnection <ZT-IP-сервера> -Port 9999`
   → `TcpTestSucceeded : True`.

Пример: сервер на Linux `10.126.245.249`, клиент на Windows `10.126.245.202` →
в поле вводится `10.126.245.249`. Если ввести собственный ZT-адрес (`...202`) или
`127.0.0.1`, на этом компьютере слушателя нет и Windows отвечает
`Connection refused`. Когда оба слота заняты, третий клиент получает
`error` «Сервер занят».

## Архитектура

| Модуль | Тип | Содержимое |
|---|---|---|
| `gamecore` | SHARED (`libgamecore.so` / `gamecore.dll`) | вшитые данные (60×139), `characterNames/questionTexts/matrix/value`, `filterCandidates`, `hintVariance`, `hintRandomForest`, `hintCatBoost` |
| `akinator_protocol` | STATIC (`libakinator_protocol.a`) | NDJSON-протокол: разбор и сборка всех 20 типов сообщений, кадрирование |
| `akinator-server` | exe | `QTcpServer`, лобби на 2 игрока, авторитетные ответы, подсказки, угадывание, реванш |
| `akinator-client` | exe | Qt Widgets GUI: подключение, выбор секрета, игровой экран, диалоги; QSS-тема и иллюстрации состояний вшиты в Qt-ресурсы |
| `tests` | exe × 2 | `tst_gamecore`, `tst_protocol` |
| `tools/generate_data.py` | офлайн-скрипт | CSV → `gamecore/generated/data.{h,cpp}` |

Игровое ядро — единственное место, где считается ответ (по таблице признаков
секрета) и работают «ML»-подсказки; сервер использует его напрямую, тесты — тоже.

## Протокол

Транспорт — TCP, кодирование — NDJSON: один JSON-объект в строке, завершённый
`\n`, UTF-8. Полное описание (20 типов сообщений, примеры, конечные автоматы
сервера и клиента) — в техническом задании `AKINATOR_BATTLE_TZ.md` (в корне
репозитория), раздел 6.

Клиент → сервер: `set_secret`, `question`, `hint`, `get_candidates`, `remove`,
`guess`, `rematch`, `leave`.

Сервер → клиент: `welcome`, `start`, `turn`, `answer`, `hint_status`,
`opponent_asked`, `candidates`, `remove_ok`, `guess_result`, `matchover`, `error`,
`opponent_disconnected`.

Пример обмена (фрагмент партии):

```json
{"type":"welcome","player":1}
{"type":"set_secret","characterId":0}
{"type":"start","players":["Player 1","Player 2"]}
{"type":"turn","player":1}
{"type":"hint_status","hintsLeft":{"variance":1,"randomforest":1,"catboost":1}}
{"type":"question","questionId":0}
{"type":"answer","questionId":0,"answer":"no","remaining":50,"hint":null}
{"type":"opponent_asked","questionId":0,"answer":"no"}
{"type":"guess","characterId":0}
{"type":"matchover","winner":2,"characterId":0,"character":"Naruto Uzumaki"}
```

## Чек-лист демонстрации

1. `cmake -S . -B build && cmake --build build` — собирается на Windows и Linux/macOS.
2. `ctest --test-dir build --output-on-failure` — все тесты зелёные.
3. `gamecore` — SHARED-библиотека (`build/bin/libgamecore.so` /
   `build\bin\gamecore.dll`), реально используемая сервером, клиентом и тестами.
4. `python3 tools/generate_data.py` — пересобирает данные из
   `data/selected_characters.csv` (результат детерминирован).
5. `GAME_SERVER_PORT=9999 ./build/bin/akinator-server` — в логе `Сервер слушает 0.0.0.0:9999`.
6. Порт доступен извне (фаервол / проброс порта).
7. Windows-клиент: собрать по разделу «Windows: сборка и подключение» (`windeployqt`
   обязателен), затем `set GAME_SERVER_HOST=<публичный_IP>` + `build\bin\akinator-client.exe`
   (или просто ввести адрес в поле «Адрес сервера»).
8. Linux/macOS-клиент с тем же адресом.
9. Оба выбирают персонажей из 60 → `start` → ход игрока 1.
10. Демонстрация: обычный вопрос → `answer`, таблица кандидатов не изменилась
    (`remaining` прежний); «Открыть таблицу» + удаление → `remove_ok` с новым
    остатком; три подсказки → лучший вопрос + автофильтрация; угадывание →
    `matchover`.
11. Env: без переменных — дефолты (`127.0.0.1`/`9999`); с `GAME_SERVER_HOST/PORT`
    — подключение к заданному адресу.
12. Разрыв: закрыть один клиент → второй видит «Противник отключился».
13. Отказ третьему игроку: `error` «Сервер занят».
